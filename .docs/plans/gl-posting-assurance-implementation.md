# خطة ترسيخ موثوقية ترحيل القيود

## الملخص
تطبيق حزمة خطوات تقنية وتشغيلية لضمان أن كل سند يُرحّل إلى `gl_transaction` بدقة، مع فحوصات تلقائية ولوحات مراقبة، انطلاقًا من توثيق قواعد الترحيل وصولًا إلى مراقبة الصحة بعد الإطلاق.

## المهام
- **spec-contracts** — توثيق قواعد الترحيل لكل نوع سند في ملف جديد `documentation/gl-posting-contracts.md` يتضمن جداول تمثيلية لحركة المدين/الدائن، الحسابات المتأثرة، حقول التكلفة، ومتطلبات الذهب.
- **code-guards** — إضافة فحوصات توازن وتكامل داخل `app/actions/voucher/helpers/gl-transaction.ts` و `process-details.ts` لضمان تساوي المدين والدائن، تطابق عدد السطور مع `vouchers_dtl`, والتحقق من مركز التكلفة عند اللزوم.
- **seed-suite** — إنشاء بيانات اختبار ثابتة وسكربت تفقد في `scripts/check-gl-posting.ts` يستدعي Server Actions لحفظ سندات نموذجية، ثم يقرأ بيانات `gl_transaction` ويقارنها مع التوقعات.
- **daily-recon** — بناء إجراء إعادة فحص يومي عبر Server Action جديدة في `app/actions/gl-transaction.action.ts` تعيد حساب القيود لسنة/شهر محدد وتعيد تقريرًا بالاختلافات مع تخزينه في جدول `gl_audit_logs` (خدمة API جديدة).
- **ui-dashboard** — إضافة قسم “صحة الترحيل” في `app/(pages)/settings/gl-transactions/page.tsx` يعرض أرقام السندات المتوازنة/غير المتوازنة، آخر إعادة ترحيل، وروابط مباشرة للسندات الشاذة.
- **user-preview** — إدراج لوحة “معاينة الترحيل” في نماذج السندات الرئيسة (`app/(pages)/forms/*VoucherClientPage.tsx`) تعرض القيود التي ستنشأ قبل الحفظ.
- **post-release-checklist** — إنشاء مستند إجراءات تشغيلية في `.docs/playbooks/post-release-gl-checklist.md` يصف خطوات التحقق اليدوية بعد كل نشر، ويشير لتشغيل السكربتات ولوحة المراقبة.
